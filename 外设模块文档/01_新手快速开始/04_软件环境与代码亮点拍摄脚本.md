# 软件环境介绍与代码亮点拍摄脚本

本文档用于补拍教程里的第 3、4 部分：

3. 软件介绍：TI 的 Keil 开发需要安装芯片支持包。
4. 代码亮点：这份交付代码解决了哪些实际问题。

## 3. 软件介绍：为什么要装 TI 芯片包

### 拍摄目标

这一段要让学生明白：

- Keil 本身只是 IDE，不一定自带 TI MSPM0G3507 的完整支持。
- 开发 `MSPM0G3507` 需要安装 TI 的 Device Family Pack，也就是芯片支持包。
- 没装芯片包时，Keil 可能打不开工程、找不到芯片、找不到 Flash 下载算法，或者调试寄存器显示不正常。

### 这套工程用到的芯片包

当前 Keil 工程使用的是：

```text
TexasInstruments.MSPM0G1X0X_G3X0X_DFP.1.3.1
```

对应芯片：

```text
MSPM0G3507
```

本机安装后的常见位置：

```text
C:\Users\用户名\AppData\Local\Arm\Packs\TexasInstruments\MSPM0G1X0X_G3X0X_DFP\1.3.1
```

### 芯片包里面主要有什么

拍摄时可以这样讲：

```text
这个芯片包不是我们的业务代码，它是 Keil 识别 TI 芯片必须用到的支持文件。里面包含 MSPM0G3507 的器件信息、寄存器描述文件、Flash 下载算法等。没有它，Keil 可能不知道这个芯片怎么选、怎么烧录、怎么调试。
```

可以重点说三项：

| 内容 | 作用 |
|---|---|
| Device 信息 | 让 Keil 能选择 `MSPM0G3507` |
| SVD/寄存器描述 | 调试时能看外设寄存器 |
| Flash Algorithm | 让 Keil 知道怎么把程序下载进芯片 Flash |

### 怎么下载安装

拍摄方式一：Keil 内安装。

```text
Keil -> Pack Installer -> 搜索 MSPM0G1X0X_G3X0X_DFP -> Install
```

拍摄方式二：网页下载。

```text
打开 Arm Keil Packs 页面，搜索 MSPM0G1X0X_G3X0X_DFP，下载 TexasInstruments.MSPM0G1X0X_G3X0X_DFP.1.3.1.pack，然后双击安装。
```

建议口播：

```text
这里一定要注意，Keil 能打开界面不代表环境完整。TI 的 MSPM0G3507 需要安装对应芯片包。我们这个工程用的是 TexasInstruments.MSPM0G1X0X_G3X0X_DFP 1.3.1。装好以后，Keil 才能正确识别 MSPM0G3507，并且使用正确的 Flash 下载算法。
```

### 没装芯片包会出现什么问题

可以列给学生：

```text
如果没有芯片包，可能会出现 Error loading software packs，或者工程里芯片显示不出来，也可能编译能过但下载时找不到 Flash Algorithm。所以如果同学拿到工程以后第一步打不开，先检查这个芯片包有没有安装。
```

### 这一段收尾口播

```text
所以软件环境至少包括三层：第一是 Keil uVision；第二是 ARM Compiler 6；第三是 TI MSPM0G3507 对应的芯片包。我们现在已经把工程配置好了，学生不需要重新建工程，但电脑上仍然要有这个芯片包，Keil 才能正常识别和下载。
```

## 4. 这份代码有什么亮点

### 总体口径

这一段不要讲得像炫技，重点说“新手少踩坑、拿来能用、问题已经替他们处理过”。

开场口播：

```text
这份代码的重点不是从零写一个复杂工程，而是把学生最容易卡住的地方提前处理好。学生拿到以后，不用自己创建 Keil 工程、不用手动添加一堆源文件，也不用重新配置启动文件、链接脚本和核心库，直接打开工程就能编译。
```

### 亮点 1：单独整理了 Keil-only 工程

说明：

```text
我们把 Keil 工程单独放到了 Dianfu_TI_G3507_Keil_Only 文件夹。这个文件夹只负责 Keil 编译下载，不和原来的 VS Code 工程、文档资料混在一起。学生只要打开 DCAR_G3507_User.uvprojx，就能进入工程。
```

解决的问题：

- 新手不知道 Keil 应该打开哪个文件。
- Keil 里误以为要打开整个文件夹。
- VS Code、源码资料、Keil 中间文件混在一起，后期不好维护。

### 亮点 2：工程配置已经配好

当前已配置：

| 项目 | 内容 |
|---|---|
| 芯片 | `MSPM0G3507` |
| 编译器 | ARM Compiler 6 |
| 芯片包 | `TexasInstruments.MSPM0G1X0X_G3X0X_DFP.1.3.1` |
| 启动文件 | `startup_mspm0g350x_uvision.s` |
| 链接脚本 | `mspm0g3507.sct` |
| 核心库 | `lib\libdcar_core_keil.lib` |
| 输出 | 自动生成 `.axf` 和 `.hex` |

口播：

```text
这里面已经选好了 MSPM0G3507，编译器用 ARM Compiler 6，启动文件、链接脚本、核心库都已经加进去了。学生不用再自己 New Project，也不用手动 Add Existing Files。
```

### 亮点 3：解决了链接脚本找不到的问题

之前遇到的问题：

```text
Could not open scatter description file Objects\DCAR_G3507_User.sct
```

处理方式：

```text
工程里加入了 Prepare_Keil_Build.cmd。每次编译前，它会自动把正确的 mspm0g3507.sct 准备到 Objects\DCAR_G3507_User.sct，避免 Clean 或换电脑以后链接脚本丢失。
```

口播：

```text
这个问题新手很难自己判断，因为代码没有错，是链接阶段找不到内存分配脚本。我们已经在工程里做了编译前准备，尽量让学生不要卡在这个地方。
```

### 亮点 4：解决了核心库 ABI 不兼容的问题

之前遇到的问题：

```text
wchart-16 clashes with wchart-32
packed-enum clashes with enum_is_int
```

处理方式：

```text
工程编译选项已经调整为和 libdcar_core_keil.lib 保持一致：wchar_t 使用 32 位，enum 使用 int。
```

口播：

```text
这个错误看起来很吓人，但本质是工程编译参数和点浮核心库不一致。我们已经把 Keil 工程参数改到和核心库一致，所以学生不需要再处理这些底层 ABI 问题。
```

### 亮点 5：把感为灰度改成数字量思路

说明：

```text
之前容易把感为灰度当成模拟量去讲，这里已经改成数字量思路。对于只有 DAT、CLK 的模块，DAT 对应代码里的 SDA，CLK 对应代码里的 SCL，当前预留接法是 DAT -> PB17，CLK -> PB18。
```

口播：

```text
这次特别注意了灰度模块的接法，不再把它讲成模拟量。程序里按数字量读取，接线也按 DAT 和 CLK 来讲，避免学生把它和历史模拟扫描方案混起来。
```

### 亮点 6：外设封装清楚，方便拍教程

说明：

```text
OLED、按键、蜂鸣器、UART、灰度模块都按独立文件封装。主程序只调用接口，不把所有逻辑堆在 main 里。
```

举例：

| 模块 | 文件 |
|---|---|
| OLED | `board_oled.c/h` |
| 按键 | `board_keys.c/h` |
| 蜂鸣器 | `board_buzzer.c/h` |
| UART | `board_uart.c/h` |
| 数字量灰度 | `digital_gray8.c/h` |

口播：

```text
这样做的好处是每个外设都能单独讲、单独测试。学生学 OLED 就看 OLED 文件，学按键就看按键文件，不用在一个很大的 main.c 里到处找代码。
```

### 亮点 7：保留排错口径

可以说：

```text
这套工程不是只追求能编译，还把常见问题都写到了教程里。比如 Keil 打开的是 .uvprojx，不是文件夹；编译重点看 0 Error；下载不上先查调试器、供电、SWD 和芯片包；传感器没反应先查 VCC、GND、信号线和模块指示灯。
```

## 5. 这一段可以怎么收尾

```text
所以这份代码的核心价值，是把底层工程配置和新手容易踩的坑提前处理掉。学生拿到以后，第一步不是重新搭工程，而是直接打开 Keil-only 工程编译；第二步按模块教程接外设；第三步再根据 OLED、串口或者模块指示灯做调试。这样教程就从“怎么搭环境”变成了“怎么使用和验证模块”。
```
