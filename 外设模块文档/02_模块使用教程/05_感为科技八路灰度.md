# 感为科技八路灰度接线与使用说明

本文档只说明“感为科技无 MCU 模拟量八路灰度”模块，不包含亚博智能模块。两个模块硬件类型不同，不能混用同一套代码。

## 1. 模块类型

感为科技这个模块是无 MCU 的模拟量版本，核心思路是：

- 模块内部用类似 `4051` 的多路选择器。
- 主控用 `AD0/AD1/AD2` 选择第几路探头。
- 模块只通过一个 `OUT` 输出当前选中通道的模拟电压。
- 主控用 ADC 读取 `OUT`，循环扫描 8 路。

它不是 UART 模块，也不是 I2C 模块。

## 2. 接线方案

当前按你指定的四个底板引脚接：

| 感为科技模块 | 点浮 MSPM0G3507 引脚 | 作用 |
|---|---|---|
| `OUT` | `PB25 / ADC0_CH4` | 模拟量输出，接 ADC |
| `AD0` | `PB18` | 通道选择 bit0 |
| `AD1` | `PB24` | 通道选择 bit1 |
| `AD2` | `PB17` | 通道选择 bit2 |
| `VCC` | `5V` | 供电 |
| `GND` | `GND` | 共地 |

注意：

- `OUT` 必须接到 ADC 脚，也就是当前的 `PB25 / ADC0_CH4`。
- `AD0/AD1/AD2` 是普通 GPIO 输出，不是串口。
- `GND` 必须共地。

## 4. 已实测校准值

当前测试得到的白底/黑底值如下：

```c
static const uint16_t gray8_white[GRAY8_CHANNELS] = {
    1131, 2901, 1973, 1656, 1778, 1382, 1283, 1076
};

static const uint16_t gray8_black[GRAY8_CHANNELS] = {
     119,  145,  141,  117,  117,  147,  141,  120
};
```

说明：

- 这组值来自当前接线和当时测试高度。
- 如果传感器安装高度、角度、地面材质变化，建议重新校准。
- 最终巡线时应使用安装到小车后的真实白底/黑线数据。

## 5. API 使用

在 `user_main.c` 顶部 include：

```c
#include "gray8.h"
#include "board_oled.h"
```

定义校准数组：

```c
static const uint16_t gray8_white[GRAY8_CHANNELS] = {
    1131, 2901, 1973, 1656, 1778, 1382, 1283, 1076
};

static const uint16_t gray8_black[GRAY8_CHANNELS] = {
     119,  145,  141,  117,  117,  147,  141,  120
};
```

初始化：

```c
Gray8_Init(gray8_white, gray8_black);
```

周期扫描：

```c
Gray8_Task();
```

读取 8 路数字状态：

```c
uint8_t mask = Gray8_GetDigital();
```

读取原始模拟量：

```c
uint16_t raw[GRAY8_CHANNELS];
Gray8_CopyRaw(raw);
```

OLED 显示：

```c
BoardOled_ShowGray8Dots(mask);
```

显示规则：

- bit 为 `1`：实心点。
- bit 为 `0`：空心圈。
- 从左到右对应第 1 到第 8 路。

## 6. 校准方法

感为科技这个模拟量模块必须校准。原因是每一路探头的亮度、安装高度、地面反光、黑线材质都不一样，不能只用一个固定阈值判断黑白。

当前封装的判断逻辑是：

1. 先保存 8 路在白底上的 ADC 值，作为 `white[]`。
2. 再保存 8 路在黑线上的 ADC 值，作为 `black[]`。
3. 程序会根据每一路自己的白底值和黑线值自动算阈值。
4. 之后调用 `Gray8_GetDigital()` 得到 8 路黑白状态。

### 6.1 校准前准备

校准前先确认：

- 传感器已经固定到小车上，不要拿在手上校准。
- 传感器离地高度和正式跑车时一样。
- 白底用正式赛道的白色区域。
- 黑线用正式赛道的黑线区域。
- 校准时不要让电机运动。
- OLED 或调试器能看到 `g_gray8.raw[]` 数值。

如果传感器还没有固定到底板上，只建议做“能不能读到数值”的测试，不建议把当时的校准值当最终值。

### 6.2 推荐校准流程

第一步，放到白底：

1. 把 8 路灰度整体放在白色地面上。
2. 保持高度和角度不动。
3. 等 OLED 或调试器里的原始值稳定。
4. 记录 `g_gray8.raw[0]` 到 `g_gray8.raw[7]`。
5. 这 8 个值就是 `gray8_white[]`。

第二步，放到黑线：

1. 把 8 路探头尽量都压在黑线上。
2. 如果黑线宽度不够，可以分批让每一路探头分别对准黑线。
3. 等原始值稳定。
4. 记录每一路对应的 `g_gray8.raw[]`。
5. 这 8 个值就是 `gray8_black[]`。

第三步，写回代码：

把白底和黑线实测值写入 `user_main.c` 里的数组：

```c
static const uint16_t gray8_white[GRAY8_CHANNELS] = {
    1131, 2901, 1973, 1656, 1778, 1382, 1283, 1076
};

static const uint16_t gray8_black[GRAY8_CHANNELS] = {
     119,  145,  141,  117,  117,  147,  141,  120
};
```

然后初始化时调用：

```c
Gray8_Init(gray8_white, gray8_black);
```

```powershell
cd C:\Users\qpzms\Desktop\STM32\TI\TI_3507_User
powershell -ExecutionPolicy Bypass -File .\build_user_gcc.ps1
```

### 6.3 用调试器快速捕获校准

如果使用调试器，可以在程序运行时设置：

```c
g_gray8_calib_cmd = GRAY8_CALIB_CMD_WHITE;
```

这会把当前 `g_gray8.raw[]` 保存为白底值。

再把传感器放到黑线上，设置：

```c
g_gray8_calib_cmd = GRAY8_CALIB_CMD_BLACK;
```

这会把当前 `g_gray8.raw[]` 保存为黑线值。

注意：运行时捕获的值在 RAM 里，断电会丢。最终稳定后要把数值写回 `user_main.c` 里的数组。

### 6.4 怎么判断校准是否成功

校准成功时应该看到：

- 放在白底上，8 路状态稳定，不会乱跳。
- 放在黑线上，对应位置能变成实心点。
- 遮挡某一路时，只有对应路或附近少数几路变化。
- `white[]` 和 `black[]` 每一路差距明显，最好相差几十到几百以上。

如果某一路白底和黑线差距很小，这一路就很难稳定判断。优先检查传感器高度、探头是否对准地面、黑线是否太窄、供电是否稳定。

### 6.5 临时测试点阵和正式校准的区别

当前工程里有一个临时测试接口：

```c
Gray8_GetTestMask();
```

它的作用是：第一次扫描时记住背景值，之后只要某一路变化超过临时阈值，就让 OLED 对应点变实心。这个接口适合在没校准时测试“传感器有没有变化”。

正式巡线不要依赖 `Gray8_GetTestMask()`，正式巡线应使用：

```c
Gray8_GetDigital();
```

也就是必须先完成白底/黑线校准，再用正式数字结果控制小车。

### 6.6 什么时候需要重新校准

出现下面情况建议重新校准：

- 传感器安装高度变了。
- 传感器角度变了。
- 换了赛道材质。
- 换了黑线胶带。
- 环境光变化特别大。
- OLED 上某几路开始误判或不灵敏。

## 7. 最小接入示例

下面是最小逻辑示例，重点看调用位置：

```c
#include "board_oled.h"
#include "gray8.h"

static const uint16_t gray8_white[GRAY8_CHANNELS] = {
    1131, 2901, 1973, 1656, 1778, 1382, 1283, 1076
};

static const uint16_t gray8_black[GRAY8_CHANNELS] = {
     119,  145,  141,  117,  117,  147,  141,  120
};

int main(void)
{
    BoardOled_Init();
    Gray8_Init(gray8_white, gray8_black);

    for (;;) {
        Gray8_Task();
        BoardOled_ShowGray8Dots(Gray8_GetDigital());
        BoardOled_Task10Hz();
    }
}
```

如果接入点浮完整小车工程，传感器调试阶段不要启动运动 sequence，避免电机上电就动。

## 8. 常见问题

### OLED 全空心或全实心

可能原因：

- 白底/黑线校准值不适合当前安装高度。
- `OUT` 没有接到 `PB25 / ADC0_CH4`。
- `AD0/AD1/AD2` 接错顺序。

### 8 路数值成对重复或顺序错乱

优先检查：

- `AD0 -> PB18`
- `AD1 -> PB24`
- `AD2 -> PB17`

4051 地址线接错会导致通道顺序错。

### 数值完全不变化

优先检查：

- 模块是否有 5V 供电。
- `GND` 是否共地。
- `OUT` 是否接到 `PB25`。
- 当前程序是否真的调用了 `Gray8_Task()`。

### 一上电电机动了

说明当前烧录的不是纯传感器测试固件，或者 `user_main.c` 里仍然调用了运动 sequence。传感器调试阶段应关闭运动逻辑，只保留 OLED、灰度扫描和必要的按键/蜂鸣器。

## 9. 和亚博智能模块的区别

| 项目 | 感为科技模拟量模块 | 亚博智能模块 |
|---|---|---|
| 是否带 MCU | 不带 | 带 |
| 通讯方式 | `OUT + AD0/AD1/AD2` | UART |
| 当前用到的四个脚 | `PB25/PB18/PB24/PB17` 全部用到 | 只用 `PB17/PB18`，`PB24/PB25` 预留 |
