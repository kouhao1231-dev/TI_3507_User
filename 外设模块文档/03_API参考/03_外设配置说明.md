# 外设配置总说明

本文档记录 TI_PMU_3507 底板 + MSPM0G3507 核心板项目中，用户侧外设模块的配置方案。写代码或改模块前，先看这里。

如果要看“当前到底用了哪些引脚、改线时改哪个文件”，请看：

- `02_引脚使用与修改指南.md`

## 当前用户侧模块需求

| 模块 | 是否需要 | 固件封装方式 |
|---|---:|---|
| OLED 屏幕 | 需要 | 独立模块 |
| 五个底板按键 | 需要 | 独立模块 |
| 蜂鸣器 | 需要 | 独立模块 |
| 光电管/独立模拟输入 | 需要 | 独立模块 |
| 普通直连 UART | 需要 | 独立模块 |

范围说明：

- 当前这一批模块只包括上表列出的硬件。
- 之前已经写过的外接 `gray8` 4051 八路灰度代码会保留，因为已经测试过；但它和底板独立光电管不是同一个模块。

不要把所有逻辑都继续塞进 `User/user_main.c`。每个模块应按下面方式封装：

- `User/Inc/<module>.h`
- `User/Src/<module>.c`

`User/user_main.c` 只负责调用模块：

```c
BoardKeys_Init();
BoardKeys_Task100Hz();
BoardBuzzer_Init();
BoardPhoto_Init();
BoardOled_Init();
BoardUart_Init();
```

## DCAR 内核资源限制

下面这些资源已经被点浮 DCAR 闭源内核使用，用户模块不要碰：

| 资源 | 状态 |
|---|---|
| `TIMA0` | 电机 PWM，内核占用 |
| `TIMG0` | 用户 1 kHz 调度，内核占用 |
| `SysTick` | 125 Hz 控制环，内核占用 |
| `SPI1` | IMU，内核占用 |
| `UART0` / `PINCM21/22` | 调试遥测，内核占用 |
| 编码器相关 GPIOA 引脚 | 内核占用 |
| 电机方向/PWM 引脚 | 内核占用 |
| Flash 校准/授权扇区 | 不要擦除 |

如果用户模块需要中断，优先级不要使用 `0/1`，避免干扰小车控制内核。

## OLED 屏幕模块

底板接口：`H14`

| H14 引脚 | 网络 | MSPM0G3507 功能 |
|---:|---|---|
| 1 | `GND` | 地 |
| 2 | `VCC_5V` | OLED 供电 |
| 3 | `PA1` / `OLED_SCL` | 当前作为 GPIO 模拟 I2C SCL |
| 4 | `PA0` / `OLED_SDA` | 当前作为 GPIO 模拟 I2C SDA |

模块文件：

- `User/Inc/board_oled.h`
- `User/Src/board_oled.c`

主要 API：

```c
void BoardOled_Init(void);
void BoardOled_Clear(void);
void BoardOled_SetLine(uint8_t line, const char *text);
void BoardOled_SetNumber(uint8_t line, const char *label, int32_t value);
void BoardOled_SetHex(uint8_t line, const char *label, uint32_t value);
void BoardOled_ShowPhotoMask(uint8_t mask);
void BoardOled_ShowStatus(const char *line0, const char *line1);
void BoardOled_Task10Hz(void);
```

注意：

- 当前 OLED 已测试点亮。
- 典型 SSD1306 地址是 `0x3C`。
- OLED 刷新要限速，例如 10 Hz，不要在高速循环里一直整屏刷新。

## 五个按键模块

底板按键为低电平有效，内部上拉。

| 按键 | MCU 引脚 | IOMUX | 状态 |
|---|---|---|---|
| `KEY1` | `PA4` | `IOMUX_PINCM9` | 低电平有效 |
| `KEY2` | `PA3` | `IOMUX_PINCM8` | 低电平有效 |
| `KEY3` | `PB19` | `IOMUX_PINCM45` | 低电平有效 |
| `KEY4` | `PB23` | `IOMUX_PINCM51` | 低电平有效 |
| `KEY5` | `PB27` | `IOMUX_PINCM58` | 低电平有效 |

模块文件：

- `User/Inc/board_keys.h`
- `User/Src/board_keys.c`

主要 API：

```c
typedef enum {
    BOARD_KEY_1 = 0,
    BOARD_KEY_2,
    BOARD_KEY_3,
    BOARD_KEY_4,
    BOARD_KEY_5,
} BoardKey;

void BoardKeys_Init(void);
void BoardKeys_Task100Hz(void);
uint8_t BoardKeys_GetPressedMask(void);
uint8_t BoardKeys_IsPressed(BoardKey key);
uint8_t BoardKeys_WasPressed(BoardKey key);
```

注意：

- 消抖在模块内部完成。
- 原理图文字里出现过 `KEY1/KEY2 -> PC0/PC1` 的旧标注，固件不要按那个用。当前确认按 `KEY1=PA4`、`KEY2=PA3`。

- `User/Inc/board_buzzer.h`

```c
void BoardBuzzer_Init(void);
```

## 光电管/独立模拟输入模块

底板提供 8 路独立模拟输入。它和外接 `感为无 MCU 八路灰度` 不一样，后者是 1 路 ADC 加 4051 地址线。

| 通道 | 接口 | MCU 引脚 | ADC 映射 |
|---:|---|---|---|
| `PHOTO1` | `H6` | `PA27` | `ADC0_CH0` |
| `PHOTO2` | `H7` | `PA26` | `ADC0_CH1` |
| `PHOTO3` | `H8` | `PA25` | `ADC0_CH2` |
| `PHOTO4` | `H9` | `PA24` | `ADC0_CH3` |
| `PHOTO5` | `H10` | `PB25` | `ADC0_CH4` |
| `PHOTO6` | `H11` | `PB24` | `ADC0_CH5` |
| `PHOTO7` | `H12` | `PB17` | `ADC1_CH4` |
| `PHOTO8` | `H13` | `PB18` | `ADC1_CH5` |

模块文件：

- `User/Inc/board_photo.h`
- `User/Src/board_photo.c`

规划 API：

```c
#define BOARD_PHOTO_CHANNELS 8U

void BoardPhoto_Init(void);
void BoardPhoto_Task100Hz(void);
void BoardPhoto_SetCalibration(const uint16_t white[BOARD_PHOTO_CHANNELS],
                               const uint16_t black[BOARD_PHOTO_CHANNELS]);
void BoardPhoto_CopyRaw(uint16_t out[BOARD_PHOTO_CHANNELS]);
void BoardPhoto_CopyNormalized(uint16_t out[BOARD_PHOTO_CHANNELS]);
uint16_t BoardPhoto_GetRaw(uint8_t channel);
uint16_t BoardPhoto_GetNormalized(uint8_t channel);
uint8_t BoardPhoto_GetDigitalMask(void);
uint8_t BoardPhoto_IsWhite(uint8_t channel);
int16_t BoardPhoto_GetLineOffset(void);
uint8_t BoardPhoto_IsOnline(void);
```

注意：

- 当前 `board_photo` 还是 API 框架，ADC 扫描未完成。
- `PHOTO7/PB17` 和 `PHOTO8/PB18` 可按实际模块配置。
- 如果后续要用满 8 路独立光电管，需要重新安排 UART 引脚。

## 巡线传感器抽象建议

上层巡线逻辑最好只看到“8 路线传感器”，不要关心底层到底是：

- 底板 8 路独立模拟光电管 `PHOTO1..PHOTO8`
- 外接 4051 八路灰度模块

建议后续做一层统一接口：

```c
LineSensor_Init();
LineSensor_Task100Hz();
LineSensor_GetRaw(ch);
LineSensor_GetDigitalMask();
LineSensor_GetLineOffset();
```

这样后面硬件换了，上层巡线算法不用大改。

## 普通直连 UART 模块

`UART0` 已被 DCAR 内核调试/遥测占用，不要用于用户模块。

模块文件：

- `User/Inc/board_uart.h`
- `User/Src/board_uart.c`

主要 API：

```c
void BoardUart_Init(void);
void BoardUart_Task(void);
BoardUartStatus BoardUart_GetStatus(void);
uint8_t BoardUart_WriteByte(uint8_t byte);
uint8_t BoardUart_Write(const uint8_t *data, uint16_t len);
uint8_t BoardUart_SendText(const char *text);
uint8_t BoardUart_SendLine(const char *text);
uint8_t BoardUart_SendNumber(const char *label, int32_t value);
uint8_t BoardUart_SendHex(const char *label, uint32_t value);
uint16_t BoardUart_Available(void);
uint8_t BoardUart_ReadByte(uint8_t *byte);
uint8_t BoardUart_ReadLine(char *out, uint8_t max_len);
const char *BoardUart_GetLastLine(void);
```

当前确认接线：

| 信号 | MCU 引脚 | IOMUX | 底板位置 |
|---|---|---|---|
| `UART2_TX` | `PB17` | `IOMUX_PINCM43_PF_UART2_TX` | `PHOTO7/H12` 信号 |
| `UART2_RX` | `PB18` | `IOMUX_PINCM44_PF_UART2_RX` | `PHOTO8/H13` 信号 |

测试说明：

- 这是普通直连 UART，不是蓝牙专用串口。
- PC 侧测试使用 CH340/USB-TTL，Windows 端口为 `COM6`。
- 串口参数：`115200 8N1`。
- USB-TTL 接线：
  - 适配器 `RXD` -> 板子 `PB17/UART2_TX`
  - 适配器 `TXD` -> 板子 `PB18/UART2_RX`
  - 适配器 `GND` -> 板子 `GND`
- 信号电平必须兼容 3.3 V，不能把信号脚接到 5 V。

已验证：

- 固件周期发送 `U2 OK\r\n`。
- PC 发送 `PING123\r\n`，板子回复 `RX:PING123\r\n`。
- PC 连续发送 `A1\r\n` 和 `B2\r\n`，板子回复 `RX:A1\r\nRX:B2\r\n`。

代价：

- 当前 UART 示例使用 `PB17/PB18`。
- 如果后续必须使用 8 路独立光电管，需要重新选择 UART 引脚。

## 其他 UART 候选引脚

| 方案 | UART | TX | RX | 状态 |
|---|---|---|---|---|
| A | `UART1` | `PB4 / IOMUX_PINCM17` | `PB5 / IOMUX_PINCM18` | 备选 |
| B | `UART2` | `PA21 / IOMUX_PINCM46` | `PA22 / IOMUX_PINCM47` | 备选 |
| C | `UART2` | `PA23 / IOMUX_PINCM53` | `PA24 / IOMUX_PINCM54` | 备选 |
| D | `UART3` | `PB2 / IOMUX_PINCM15` | `PB3 / IOMUX_PINCM16` | 备选 |
| E | `UART3` | `PA26 / IOMUX_PINCM59` | 无合适相邻 RX | 不是完整收发对 |

当前结论：

- 当前用户 UART 采用 `UART2 PB17/PB18`。
- 如果后续硬件需求变化，改线前重新核对引脚复用功能。

## 推荐实现顺序

1. 保持 `board_keys`、`board_buzzer`、`board_oled`、`board_uart` 独立封装。
2. 完成 `board_photo` 的 ADC 扫描实现。
3. 如果最终使用外接 Gray8，先重选 `AD0/AD1/AD2`，再做统一 `LineSensor` 抽象。
4. 上层比赛流程只调用模块 API，不直接操作寄存器。
