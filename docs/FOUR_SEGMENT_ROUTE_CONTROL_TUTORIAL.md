# DCar 高精度里程计驱动的二轮小车四段式高速路径控制

> DCar 里程计的测量精度和短时重复性远高于二轮小车的机械执行精度。车辆跑偏时，里程计并不是“算错了”，而是在准确记录车辆因轮子安装、有效轮径、轮距、轮胎接触和车架装配误差而产生的真实偏移。

## 整体结论

固定赛道上的高速运行不需要让一种控制方法承担全部任务。最稳定的结构是把一个周期拆成四段，并为每一段选择最可信的控制依据：

```text
大半圆
→ 第一小转角
→ 斜线直行
→ 第二小转角回正
```

四段分别采用：

| 运动段 | 控制方式 | 正常结束依据 |
|---|---|---|
| 大半圆 | `Dcar_Arc()` | 圆弧 API 完成 |
| 第一小转角 | 保持线速度、转向打满 | DCar 原始短时相对 yaw 到达释放角 |
| 斜线直行 | 固定速度流式指令 | 标定速度 × 8 ms × 指令次数 |
| 第二小转角 | 保持线速度、反向转向打满 | DCar 原始短时相对 yaw 到达回正释放角 |

完整系统建立在五条原则上：

1. **相信 DCar 里程计的短时相对航向。**
2. **把车辆真实跑偏归因于机械系统，而不是里程计随机失真。**
3. **把路径拆成职责明确、参数独立的四个运动段。**
4. **左右周期分别标定，显式接纳车辆机械不对称。**
5. **运动优先，串口和灰度等可选模块不能干扰流式控制。**

下文分为两个可独立阅读的部分：

- **实操篇**：直接说明如何运行、调参、测试和判断结果。
- **原理篇**：完整解释机械误差、局部里程计、转向释放、直线模型和实时调度。

# 第一部分　实操篇

实操篇包含完整运行信息，不要求先理解后面的数学推导。

## 1. 一分钟了解系统

### 1.1 一个周期

一次左周期或右周期包含：

```text
1. 大半圆
2. 第一小转角
3. 斜线直行
4. 第二小转角回正
```

### 1.2 四圈任务

四圈一共执行八个周期：

```text
L1 → R1 → L2 → R2 → L3 → R3 → L4 → R4
```

其中：

- `L` 表示左周期；
- `R` 表示右周期；
- 左右周期严格交替；
- 中间周期不停车；
- 第八个周期结束后停车。

### 1.3 两种运行方式

同一套四段控制支持：

| 模式 | 行为 | 用途 |
|---|---|---|
| 单周期模式 | 每按一次 K1 只运行一个 L 或 R 周期 | 独立标定 |
| 四圈连续模式 | 每按一次 K1 连续运行 8 个 L/R 周期 | 最终任务 |

单周期模式和连续模式使用完全相同的四段函数和参数。模式切换只改变一次 K1 触发多少个周期，不改变任何运动算法。

## 3. 上电与按键操作

### 3.1 K1：启动与急停

K1 位于开发板 PA18：

- 停车待命时按一次：开始任务；
- 单周期模式：运行一个周期；
- 四圈连续模式：运行八个周期；
- 运动中再次按下：立即请求急停。

停车日志发送期间按下的 K1 会被保留为下一次启动请求，不会因为串口输出而被清除。

### 3.2 K2：IMU 零偏校准

K2 位于 PB21：

1. 车辆水平放在稳定台面；
2. 上电或 Reset；
3. 本次上电不能先按 K1；
4. 按下并松开 K2；
5. 串口出现 `GC,BEGIN`；
6. 约 4 秒后出现 `GC,DONE`；
7. 继续静置；
8. 人工 Reset 后重新进入正常待命。

校准模式是单向状态。`GC,DONE` 后不会直接开始运动，必须 Reset。

### 3.3 同时按键

K1 和 K2 在同一个 100 Hz 回调中采样并进行约 30 ms 去抖。

同一采样周期两键同时触发时，K2 优先，防止校准请求与运动启动同时发生。

## 4. 第一段实操：大半圆

### 4.1 实际指令

```c
Dcar_Arc(command_radius,
         direction * ARC_DYAW,
         RUN_SPEED);
```

其中：

```text
command_radius = 0.40 / 2.22
               ≈ 0.1802 m
```

左右方向：

```text
左周期：direction = +1，dyaw = +3.12 rad
右周期：direction = -1，dyaw = -3.12 rad
```

### 4.2 大半圆结束后的动作

大半圆返回后立即：

1. 封存本次圆弧出口的灰度观测；
2. 读取 DCar 当前 yaw；
3. 把这个 yaw 定义为本周期局部 0°；
4. 选取本方向独立参数；
5. 进入第一小转角。

应用层不在圆弧与第一小转角之间额外调用 `Dcar_Stop()`。

### 4.3 大半圆的验收标准

独立重复运行左右半圆，观察：

- 圆弧半径是否稳定；
- 终点是否集中；
- 最终 yaw 是否集中；
- 左右方向是否分别重复；
- 是否出现偶发变速或甩尾；
- 同一方向多次轨迹是否基本平行。

大半圆已经稳定后，不使用后续小转角参数掩盖圆弧误差。

## 5. 第二段实操：第一小转角

### 5.1 控制行为

第一小转角保持：

```text
vx = 0.36
```

转向未释放时：

```text
左周期：yaw_delta = +0.75
右周期：yaw_delta = -0.75
```

每 8 ms 读取一次 DCar 原始 yaw，并换算为相对于圆弧出口的局部 yaw。

达到本方向释放角后：

```c
Dcar_Drive(0.36f, 0.0f);
```

随后立即进入直线。

### 5.2 第一释放角不是阻塞转角命令

`+0.85 rad` 不表示向 DCar 下发“转 0.85 rad”的阻塞动作。

它表示：

```text
持续发送最大左转需求
→ 读取相对 yaw
→ yaw 达到 +0.85 rad
→ 取消继续增加航向
```

右周期同理：

```text
持续发送最大右转需求
→ yaw 达到 -0.8335 rad
→ 取消继续增加航向
```

### 5.3 如何调左周期

观察左周期斜线方向：

| 现象 | 调整 |
|---|---|
| 直线过度偏左 | 减小 `LEFT_TURN_IN_RELEASE_YAW` |
| 直线偏右、左转不足 | 增大 `LEFT_TURN_IN_RELEASE_YAW` |

每次建议只改变较小角度，例如：

```text
0.01 rad ≈ 0.57°
0.02 rad ≈ 1.15°
```

### 5.4 如何调右周期

| 现象 | 调整 |
|---|---|
| 直线过度偏右 | 让 `RIGHT_TURN_IN_RELEASE_YAW` 向 0 靠近 |
| 直线偏左、右转不足 | 让 `RIGHT_TURN_IN_RELEASE_YAW` 变得更负 |

### 5.5 第一小转角验收标准

- 转向指令在释放前始终保持同一符号；
- 释放以后不反向追角；
- 进入直线时没有停车；
- 同一方向直线倾斜角重复；
- 调整释放角时，直线倾斜方向按预期变化。

## 6. 第三段实操：斜线直行

### 6.1 控制行为

直线段持续发送：

```c
Dcar_Drive(0.36f, 0.0f);
```

直线开始时：

```text
segment_progress = 0
```

每 8 ms 增加一次模型距离：

```text
segment_progress += 0.36 × 2.02 × 0.008
```

每次增加：

```text
0.0058176 m
≈ 5.82 mm
```

达到本方向目标距离后，结束直线段。

### 6.2 当前左右持续时间

左周期：

```text
目标距离 = 1.04 m
控制次数 ≈ 179
持续时间 ≈ 1.432 s
```

右周期：

```text
目标距离 = 1.02 m
控制次数 ≈ 176
持续时间 ≈ 1.408 s
```

### 6.3 如何调直线距离

先保证第一小转角形成的方向基本正确，再调直线：

| 现象 | 调整 |
|---|---|
| 沿斜线方向走得不足 | 增大对应方向直线距离 |
| 沿斜线方向走得过多 | 减小对应方向直线距离 |

不要使用直线距离修复明显的斜线角度错误。角度错误应先调整第一释放角。

### 6.4 独立进度原则

直线距离只属于直线段：

- 第一小转角走过的距离不从直线目标中扣除；
- 第二小转角需要的距离不提前从直线目标中预留；
- 每次进入直线都从 0 开始累计；
- 左右周期分别使用自己的目标距离。

### 6.5 直线验收标准

- 全段 `yaw_delta` 为 0；
- 速度指令保持 0.36；
- 没有中途突然加速；
- 没有串口输出打断 8 ms 刷新；
- 左右周期各自的直线持续时间稳定；
- 单周期和连续模式下同方向表现接近。

## 7. 第四段实操：第二小转角回正

### 7.1 控制行为

第二小转角与第一小转角使用相同的“打满—释放”机制，但方向相反。

左周期第一小转角把 yaw 拉到正方向，因此第二小转角发送负转向需求。

右周期第一小转角把 yaw 拉到负方向，因此第二小转角发送正转向需求。

### 7.2 当前释放角

```text
左周期：+0.12 rad
右周期：-0.12 rad
```

换算：

```text
0.12 rad ≈ 6.88°
```

它们是释放点，不是最终希望静止的角度。

### 7.3 如何调左周期回正

| 现象 | 调整 |
|---|---|
| 左周期回正不足，仍保留过多正角度 | 减小 `LEFT_TURN_OUT_RELEASE_YAW`，使其靠近 0 |
| 左周期回正过度 | 增大 `LEFT_TURN_OUT_RELEASE_YAW` |

### 7.4 如何调右周期回正

| 现象 | 调整 |
|---|---|
| 右周期回正不足，仍保留过多负角度 | 增大 `RIGHT_TURN_OUT_RELEASE_YAW`，使其靠近 0 |
| 右周期回正过度 | 减小该值，使其更负 |

### 7.5 回正验收标准

- 转向释放由 DCar 原始相对 yaw 决定；
- 达到释放点后立即把 `yaw_delta` 归零；
- 不在释放后反向扭头；
- 单周期停止时最终姿态可重复；
- 连续模式中直接进入下一大半圆，不插入停车。

## 8. 完整标定顺序

参数标定必须遵守因果顺序。

### 8.1 第一步：只确认大半圆

重复运行左右大半圆，确认圆弧本身稳定。

这一阶段不调整：

- 第一释放角；
- 直线距离；
- 第二释放角；
- 灰度修正。

### 8.2 第二步：只调第一小转角

目标是让斜线方向正确。

每次只改一个方向的第一释放角，不同时改直线距离。

记录：

- 修改前参数；
- 修改后参数；
- 直线角度向哪一侧变化；
- 周期最终 X/Y 暂时不作为主要判断。

### 8.3 第三步：只调直线距离

第一小转角基本准确后，再调沿直线方向的运动长度。

记录：

- 实际终点相对目标点是超前还是落后；
- 误差厘米数；
- 左右方向分别记录；
- 不用另一方向参数补偿本方向。

### 8.4 第四步：只调第二小转角

只观察周期结束后的车头方向：

- 左偏多少度；
- 右偏多少度；
- 调整后变化是否符合方向规律。

### 8.5 第五步：单周期重复性

至少重复多次同方向周期，确认：

- 端点集中；
- 姿态集中；
- 运动形态一致；
- 没有偶发指令中断；
- 串口和灰度不改变运动效果。

### 8.6 第六步：四圈连续运行

观察：

- 第一圈与后续圈是否一致；
- 左周期是否始终使用左参数；
- 右周期是否始终使用右参数；
- 周期边界是否停车；
- 最终只在第八周期后停车；
- 单周期参数在连续运行中是否仍有效。

### 8.7 第七步：可选灰度鲁棒性

基础路线稳定后，再通过人为改变初始横向位置验证灰度修正。

灰度纠偏一次只做小幅修正，并设置最大修正量，不能让一次错误亮灯覆盖基础参数。

## 9. 灰度端点修正

### 9.1 默认状态

基础运动不依赖灰度。

默认行为：

```text
灰度持续采样
→ 记录圆弧出口观测
→ 写入停车日志
→ 不修改六个基础运动参数
```

即使：

- 灰度模块没有连接；
- I2C 地址扫描失败；
- 运行中灰度读取失败；

基础四段路线仍然可以运行。

### 9.2 八路权重

从车左到车右：

```text
-7, -5, -3, -1, +1, +3, +5, +7
```

黑线重心：

\[
c=\frac{\sum_i w_i b_i}{\sum_i b_i}
\]

其中：

```text
b_i = 1：第 i 路检测到黑线
b_i = 0：第 i 路未检测到黑线
```

### 9.3 当前横向映射

\[
e_y
=
\operatorname{clip}(-0.50c,-4,4)
\]

单位为厘米。

### 9.4 开启修正后的直接映射

灰度只对下一段计划做有限直接修正：

\[
\theta_{\text{in}}'
=
\theta_{\text{in}}+k_\theta e_y
\]

\[
s'
=
s+k_s e_y
\]

\[
\theta_{\text{out}}'
=
\theta_{\text{out}}
\]

当前实验系数：

| 周期 | \(k_\theta\) | \(k_s\) |
|---|---:|---:|
| 左周期 | 0.005 rad/cm | 0.008 m/cm |
| 右周期 | 0.008 rad/cm | -0.005 m/cm |

灰度只修正它能够观察的横向偏差，不接管整段转向。

## 10. 运动期间的日志规则

### 10.1 为什么不能实时打印长文本

流式控制依赖稳定的 8 ms 刷新。

运动中发送大量串口文本可能造成：

- 主流程等待串口；
- 刷新间隔变化；
- 同一套参数在不同圈表现不同；
- 串口拔掉后控制异常；
- 调试行为改变运动本身。

### 10.2 固定内存记录

每个周期只保存一条 44 bytes 紧凑记录。

四圈八个周期：

\[
44\times8=352\text{ bytes}
\]

内存占用固定，不会无限增长。

### 10.3 每条记录包含

- 周期编号；
- 左右方向；
- 状态；
- 灰度有效标志；
- 灰度黑线掩码；
- 灰度修正值；
- 第一释放角；
- 直线距离；
- 第二释放角；
- 三个流式阶段的控制周期数；
- 四个关键端点的局部 X/Y/yaw。

### 10.4 发送时机

```text
运动中：只存内存
最终停车：统一发送
故障停车：停车后发送已有记录
```

无线串口没有连接时允许丢日志，不允许阻止运动。

## 11. 故障边界

### 11.1 必须停车的核心故障

| 条件 | 动作 |
|---|---|
| `Dcar_Arc()` 返回失败 | 停车 |
| `Dcar_Drive()` 拒绝指令 | 停车 |
| IMU 核心异常 | 停车 |
| 编码器/电机核心异常 | 停车 |
| 小转角超过 1800 ms | 停车 |
| 直线超过 3500 ms | 停车 |
| 运动中按 K1 | 停车 |

### 11.2 不能影响运动的可选故障

| 条件 | 动作 |
|---|---|
| 灰度未连接 | 使用基础参数 |
| 灰度连续读取失败 | 本次上电停用灰度 |
| UART 未连接 | 继续运动 |
| UART 发送失败 | 丢弃日志 |

核心运动采用故障停车，可选模块采用失效继续。

# 第二部分　原理篇

原理篇从物理和数学角度完整解释系统，不依赖实操篇中的操作步骤。

## 15. 最重要的认识：车辆跑偏不等于里程计不准

### 15.1 测量系统与执行系统必须分开

一辆车包含两个不同问题：

1. **车辆实际上怎样运动；**
2. **里程计怎样记录这次运动。**

当轮子安装不平行时，直线指令可能让车辆真实产生轻微曲线。

如果 DCar 里程计随后报告了这个横向变化，它做的是正确测量：

```text
机械系统让车偏了
→ 车辆真实位置发生变化
→ DCar 里程计准确记录变化
```

不能把“车辆没有走在理想轨迹上”直接称为“里程计测错”。

更准确的关系是：

```text
理想控制命令
→ 受到机械安装影响
→ 产生真实非理想运动
→ 高精度里程计记录真实运动
```

### 15.2 DCar 里程计的优势

当前实车测试体现出以下特点：

- 同一方向多次 yaw 轨迹高度平行；
- 相同转向释放角产生相近结果；
- 短时间相对 yaw 重复性很高；
- 圆弧运动端点具有高一致性；
- 横向偏差方向长期固定，而不是无规律跳变；
- 时序干扰消除后，相同指令的重复性显著提高。

这些现象表明：

> DCar 里程计足够精确，精确到能够暴露车辆机械安装中原本不容易直接看见的细小偏差。

### 15.3 为什么误差呈固定方向

如果问题来自无规律测量波动，重复运行的偏差方向和大小应明显散开。

实际观测是：

- 同一方向总是向相近一侧偏；
- 左右周期具有各自稳定特点；
- 多次曲线彼此接近平行；
- 参数改变后，结果按固定方向变化。

这说明本任务中的主导偏差是机械系统性偏差。

在当前任务尺度内，DCar 测量波动远小于车辆机械执行偏差，不是控制结果的主要矛盾。

### 15.4 机械误差包括什么

主导来源包括：

- 左右轮有效半径差异；
- 左右轮安装方向不完全平行；
- 轮轴与车架中心线不完全垂直；
- 实际轮距与理想轮距不同；
- 左右轮胎形变不同；
- 左右轮对地接触压力不同；
- 重心偏左或偏右；
- 电机和减速机构左右响应不同；
- 地面与轮胎接触产生方向性滑移；
- 传感器、车架和轮轴之间存在安装角误差。

这些因素属于车辆机械执行系统。它们会让“相同的理想指令”产生稳定但不完全对称的真实运动。

## 16. 差速二轮车为什么容易出现横向系统偏差

理想差速运动学：

\[
v=\frac{v_r+v_l}{2}
\]

\[
\omega=\frac{v_r-v_l}{b}
\]

其中：

- \(v_l\)：左轮实际线速度；
- \(v_r\)：右轮实际线速度；
- \(b\)：左右轮中心距；
- \(v\)：车体前向速度；
- \(\omega\)：车体角速度。

理想直线要求：

\[
v_l=v_r
\]

此时：

\[
\omega=0
\]

### 16.1 有效轮径差异

设左右轮理想速度相同，但有效比例分别为：

\[
v_l=(1+\varepsilon_l)v^*
\]

\[
v_r=(1+\varepsilon_r)v^*
\]

则：

\[
\omega_{\text{mechanical}}
=
\frac{(\varepsilon_r-\varepsilon_l)v^*}{b}
\]

只要：

\[
\varepsilon_r\ne\varepsilon_l
\]

车辆真实运动就会产生稳定曲率。

DCar 里程计会准确测到这个真实角度变化，而不是凭空制造它。

### 16.2 轮子不平行

理想模型假设两轮滚动方向平行。

若左轮和右轮的滚动方向存在安装夹角：

- 轮胎会产生侧向力；
- 车体会出现轻微偏航；
- 接触点会发生方向性滑移；
- 相同前进命令会产生固定方向的弯曲。

这个误差无法仅用“左右编码器转数相等”消除，因为两个轮子即使转数相等，滚动方向也不再满足理想几何。

### 16.3 横向误差如何累积

位姿方程：

\[
\dot{x}=v\cos\theta
\]

\[
\dot{y}=v\sin\theta
\]

\[
\dot{\theta}=\omega
\]

若机械安装产生固定偏航率：

\[
\omega=\omega_b
\]

则：

\[
\theta(t)=\theta_0+\omega_b t
\]

小角度条件下：

\[
e_y\approx L\delta\theta
\]

总路程 \(L\) 越长，横向误差越明显。

因此，长期横向偏移是机械偏差经过运动学积分后的结果，不是 DCar 里程计精度不足。

## 17. 为什么不长期使用全局 X/Y 控制

### 17.1 原因不是里程计差

DCar 世界坐标记录从上电开始的真实运动：

```text
x_world
y_world
yaw_world
```

如果车辆因为机械安装在第一圈真实偏移了 3 cm，世界坐标应该把这 3 cm 记录下来。

第二圈开始时，这个真实偏移仍然存在。继续用全局坐标规划时，控制器面对的是：

```text
初始摆放误差
+ 第一圈机械执行偏差
+ 第二圈新产生的机械执行偏差
+ 后续所有真实偏移
```

不长期依赖全局 X/Y，是为了避免让固定赛道控制持续追逐机械系统累积出的复杂二维偏差，而不是因为 DCar 里程计无法测量。

### 17.2 选择最强信息

实车结果表明：

- 短时相对 yaw 极其可靠；
- 大半圆 API 重复性高；
- 固定时序下的直线模型可标定；
- 长距离二维机械偏移会逐步累积。

因此，控制器只提取最强信息：

```text
转向：使用短时相对 yaw
直线：使用稳定速度模型
全局横向位置：需要时由外部地标纠正
```

## 18. 分段局部里程计

### 18.1 建立局部原点

每个大半圆结束后，记录：

\[
\mathbf{p}_0=
\begin{bmatrix}
x_0\\
y_0\\
\theta_0
\end{bmatrix}
\]

其中：

- \(x_0\)：圆弧出口世界 X；
- \(y_0\)：圆弧出口世界 Y；
- \(\theta_0\)：圆弧出口世界 yaw。

### 18.2 局部 yaw

\[
\theta_{\text{local}}
=
\operatorname{wrap}(\theta_{\text{world}}-\theta_0)
\]

所以：

```text
圆弧刚结束：local yaw = 0
第一小转角：local yaw 逐渐接近 ±第一释放角
第二小转角：local yaw 逐渐回到 ±第二释放角
```

所有释放角都具有相对于圆弧出口的固定意义。

### 18.3 局部 X/Y

\[
\Delta x=x_{\text{world}}-x_0
\]

\[
\Delta y=y_{\text{world}}-y_0
\]

旋转到局部车体系：

\[
x_{\text{local}}
=
(\Delta x\cos\theta_0+\Delta y\sin\theta_0)k_x
\]

\[
y_{\text{local}}
=
(-\Delta x\sin\theta_0+\Delta y\cos\theta_0)k_y
\]

当前：

\[
k_x=2.02
\]

\[
k_y=2.06
\]

局部 X/Y 用于端点分析和日志，基础运动不使用它们判断直线结束。

### 18.4 局部化的价值

局部化不会否定世界里程计，反而利用了它的高精度：

1. 读取准确世界 yaw；
2. 从当前准确值建立新参考；
3. 只观察短时间增量；
4. 避免历史机械位移影响本次释放角定义。

它等价于每个周期重新建立一个局部测量坐标系，而不是重置 DCar 内部里程计。

## 19. 大半圆为什么单独使用运动原语

大半圆具有固定半径和固定转角：

\[
R=0.40\text{ m}
\]

\[
\Delta\theta\approx\pi
\]

经过实车标定后：

\[
R_{\text{cmd}}
=
\frac{0.40}{2.22}
\approx0.1802\text{ m}
\]

\[
\Delta\theta_{\text{cmd}}=3.12\text{ rad}
\]

`Dcar_Arc()`把以下控制封装在成熟内核中：

- 线速度控制；
- 航向变化；
- 圆弧完成判断；
- IMU与编码器底层协同；
- 异常状态返回。

应用层重复实现圆弧控制只会增加参数和状态。把稳定原语视为不可拆分动作，可以减少上层控制的不确定性。

## 20. 饱和转向与释放边界

### 20.1 数学定义

设：

- 当前局部 yaw 为 \(\theta\)；
- 释放角为 \(\theta_r\)；
- 方向符号为 \(s\)；
- 最大转向需求为 \(u_{\max}=0.75\)。

剩余角：

\[
e_\theta
=
\operatorname{wrap}(\theta_r-\theta)
\]

控制律：

\[
u_{\text{yaw}}
=
\begin{cases}
s u_{\max},&s e_\theta>0\\
0,&s e_\theta\le0
\end{cases}
\]

### 20.2 它不是比例控制

比例控制通常为：

\[
u=K_p e
\]

接近目标时会逐渐减小转向需求。

四段式小转角使用：

```text
未到释放点：始终打满
到达释放点：立即归零
```

优点：

- 转向时间短；
- 行为简单；
- 只有一个可调角度；
- 不会因比例参数不同产生缓慢拖尾；
- 不需要建立小圆角半径模型；
- 容易验证转向指令符号。

### 20.3 单向释放

释放状态一旦成立，本段不会重新激活。

这避免：

```text
越过目标
→ 反向修正
→ 再次越过
→ 左右摆动
```

四段式控制关心的是高速路径衔接，不是停车后的静态角度伺服。

## 21. 静态惯性补偿

### 21.1 释放后仍会继续旋转

在释放时刻 \(t_r\)：

```text
yaw_delta 从 ±0.75 变为 0
```

车辆角速度不会瞬间变为零。

释放后的残余转角：

\[
\Delta\theta_{\text{residual}}
=
\int_{t_r}^{t_s}\omega(t)\,dt
\]

最终角度：

\[
\theta_{\text{final}}
\approx
\theta_{\text{release}}
+\Delta\theta_{\text{residual}}
\]

### 21.2 释放角的构成

要达到几何目标 \(\theta_{\text{target}}\)：

\[
\theta_{\text{release}}
\approx
\theta_{\text{target}}
-\Delta\theta_{\text{residual}}
\]

人工标定的释放角综合吸收：

- 目标几何方向；
- 机械惯性；
- 轮胎侧向变形；
- 左右机械不对称；
- DCar 内部控制响应；
- 8 ms 采样量化；
- 从转向切换到直线的动态过程。

### 21.3 为什么第二释放角不是零

第二小转角的几何目标接近 0°，但当前释放点为：

```text
LEFT  +0.12 rad
RIGHT -0.12 rad
```

原因是：

```text
在到达 0° 之前停止继续施加转向
→ 车辆利用剩余角速度继续回正
→ 最终姿态接近理想方向
```

这是一种稳定、可重复、容易人工标定的提前释放方式。

## 22. 直线恒速模型

### 22.1 基本公式

设：

- 速度命令 \(v_{\text{cmd}}\)；
- 实车等效比例 \(k_d\)；
- 控制周期 \(\Delta t\)；
- 指令次数 \(N\)。

等效模型速度：

\[
v_{\text{model}}=v_{\text{cmd}}k_d
\]

累计距离：

\[
s_N=Nv_{\text{cmd}}k_d\Delta t
\]

### 22.2 当前数值

\[
v_{\text{cmd}}=0.36
\]

\[
k_d=2.02
\]

\[
\Delta t=0.008
\]

\[
v_{\text{model}}
=
0.36\times2.02
=
0.7272\text{ m/s}
\]

\[
\Delta s
=
0.7272\times0.008
=
0.0058176\text{ m}
\]

### 22.3 `DIST_CAL`表示什么

实车曾观测到命令尺度与实际运动尺度存在稳定比例：

```text
命令约 1 m
实际运动约 2.04 m
```

采用：

```text
DIST_CAL = 2.02
```

这是“控制命令到车辆真实机械位移”的系统标定。

它不表示 DCar 里程计随机测错，而表示闭源内核参数、车轮有效尺寸、减速机构和实际机械结构共同形成的命令尺度与当前车辆真实尺度不同。

### 22.4 为什么模型可以稳定

恒速模型有效的条件：

1. 进入直线前车辆已经在运动；
2. 四段线速度保持相同；
3. 不发生停车再加速；
4. 8 ms 刷新周期稳定；
5. 串口不在运动中阻塞；
6. 左右方向分别标定；
7. 相同机械状态下实际平均速度具有高重复性。

### 22.5 为什么不用 X/Y 终止直线

当前直线目标只需要高度重复的段长，不需要重建完整地图位姿。

使用固定模型可以：

- 避免历史机械偏移进入本段进度；
- 保证单周期和连续模式使用同一终止逻辑；
- 让直线只有一个可调参数；
- 避免 X/Y 坐标方向与斜线投影之间再次耦合。

DCar 的 X/Y 仍然被记录用于验证车辆真实运动，只是不参与当前直线段的停止决策。

## 23. 速度连续性的物理意义

### 23.1 停车会改变机械初始条件

频繁停车会引起：

- 车身俯仰；
- 重心转移；
- 轮胎形变释放；
- 静摩擦与动摩擦切换；
- 电机重新起步；
- 航向控制重新建立；
- 每段起始速度不同。

即使指令参数完全相同，起始机械状态不同也可能产生不同结果。

### 23.2 四段共同线速度

```text
大半圆：0.36
第一小转角：0.36
直线：0.36
第二小转角：0.36
```

第一小转角改变的是转向需求，不是线速度。

第二小转角同样只改变转向需求。

持续前进使各段边界的机械状态更接近，增强参数重复性。

### 23.3 连续周期

中间周期结束时：

```text
最后一条流式指令仍为 Dcar_Drive(0.36, 0)
→ 不调用 Dcar_Stop
→ 进入下一次 Dcar_Arc
```

应用层不主动制造速度断点。

## 24. 左右解耦的数学意义

如果强制左右镜像：

\[
\theta_{\text{in},R}
=
-\theta_{\text{in},L}
\]

\[
s_R=s_L
\]

\[
\theta_{\text{out},R}
=
-\theta_{\text{out},L}
\]

就等于假设：

- 左右轮完全一致；
- 车架完全对称；
- 重心在几何中心；
- 左右摩擦相同；
- 两个方向动态响应完全镜像。

实车不满足这些理想条件。

因此采用两个参数向量：

\[
\mathbf{p}_L
=
\begin{bmatrix}
0.85\\
1.04\\
0.12
\end{bmatrix}
\]

\[
\mathbf{p}_R
=
\begin{bmatrix}
-0.8335\\
1.02\\
-0.12
\end{bmatrix}
\]

这不是对机械误差的妥协，而是对真实车辆的正确建模。

## 25. 灰度端点为什么主要修正 Y

### 25.1 传感器几何

八路灰度横向排列，垂直于车辆前进方向。

在圆弧端点扫过黑线时，不同通道最后接触黑线的位置反映车体相对于地标的横向关系。

### 25.2 可观测信息

当圆弧出口 yaw 已经稳定时：

- 黑线重心主要反映横向偏差；
- 通道组合可判断偏左或偏右；
- 已知地标为局部坐标提供绝对参照。

单次通道组合不能独立给出：

- 沿黑线方向的完整 X；
- 完整绝对 yaw；
- 三自由度全局位姿。

因此，灰度只做有限 Y 修正最合理。

### 25.3 为什么是事件修正

灰度在硬件层持续采样，但只有圆弧出口的“最后黑线事件”被用于本周期。

这同时满足：

- 不使用持续循迹；
- 不让灰度实时抢夺转向控制；
- 不让后续路段偶然扫线覆盖端点结果；
- 外部地标只在明确时刻修正机械偏差累积。

## 26. 实时调度为什么决定重复性

### 26.1 控制周期

\[
\Delta t=8\text{ ms}
\]

\[
f=125\text{ Hz}
\]

直线距离、转向检测和指令刷新都依赖这个周期。

若实际周期变化：

\[
s_N=Nv\Delta t
\]

中的 \(\Delta t\) 也会变化，导致相同指令次数产生不同距离。

### 26.2 运动中长串口的影响

如果串口发送占用主流程：

```text
8 ms 到期
→ 主流程仍在等待 UART
→ 下一条 Dcar_Drive 延迟
→ 实际控制周期变化
```

这类异常属于软件时序干扰，不属于 DCar 里程计测量问题。

### 26.3 灰度 I2C 的影响

灰度采样必须：

- 只有一个总线所有者；
- 操作时间有界；
- 失败后快速退出；
- 不在主运动循环中阻塞重试；
- 不能因为未连接而阻止启动。

### 26.4 急停竞争

若回调执行：

```text
Dcar_Stop()
```

主流程紧接着执行：

```text
Dcar_Drive(...)
```

车辆可能被重新启动。

因此：

```text
检查急停标志
→ 提交流式指令
```

必须在同一个短临界区完成。

## 27. 系统的信任层级

从最可信到最需要限制使用：

### 第一层：DCar 短时相对 yaw

- 精度高；
- 重复性高；
- 直接反映车辆真实转向；
- 用于两个小转角释放。

### 第二层：DCar 大半圆运动原语

- 已经过实车标定；
- 同一方向重复性高；
- 直接完成固定半圆。

### 第三层：固定时序下的机械速度模型

- 不追求完整动力学；
- 通过实车比例和左右距离标定；
- 用于直线段。

### 第四层：DCar 世界 X/Y 日志

- 准确记录车辆真实运动；
- 用于分析机械偏差；
- 不作为当前基础直线的长期控制目标。

### 第五层：灰度端点地标

- 低频；
- 提供地图绝对参照；
- 主要限制机械系统累积出的横向偏差。

## 28. 系统优势

### 28.1 充分利用 DCar 里程计优势

控制器没有因为车辆跑偏而否定里程计，而是提取其最强能力：

- 高精度短时 yaw；
- 高重复性增量变化；
- 对机械真实运动的忠实记录。

### 28.2 不让机械误差污染全部控制

机械安装偏差被限制在：

- 左右独立参数；
- 每周期局部坐标；
- 必要时的灰度端点修正。

### 28.3 高速

三个连接段采用流式控制，避免频繁停车和重新起步。

### 28.4 可解释

每个参数具有单一主要职责：

```text
第一释放角：斜线方向
直线距离：斜线长度
第二释放角：最终回正
```

### 28.5 可标定

任何修改都能明确追踪到一个方向和一个运动段。

### 28.6 低硬件复杂度

基础路线只依赖 DCar 已有硬件。灰度是增强鲁棒性的可选地标。

### 28.7 故障隔离

可选模块失效不改变运动核心，核心运动异常才停车。

### 28.8 易于维护

按键、运动、灰度、日志和纯数学逻辑分别位于独立模块。

---

## 29. 系统边界

### 29.1 仍需合理初始摆放

没有外部地标介入时，地图坐标仍由人工摆放建立。

### 29.2 机械状态变化后需要复核

以下变化可能改变标定参数：

- 更换轮胎；
- 拆装车轮；
- 改变轮距；
- 改变载荷；
- 改变重心；
- 更换地面；
- 改变运行速度。

### 29.3 直线模型不能识别临时严重打滑

恒速模型依赖机械运动重复性。若发生明显临时打滑，模型本身无法知道。

### 29.4 灰度不是完整定位

单个端点观测主要限制 Y，不能独立恢复完整 X/Y/yaw。

### 29.5 大半圆必须先稳定

如果圆弧出口姿态不稳定，后续局部零点和灰度观测都会失去统一参考。

## 30. 最终主干

```text
基础事实：
    DCar 里程计精度高于车辆机械执行精度。
    车辆偏离理想路线的主导原因是机械安装和机械运动不对称。
    里程计准确记录了这种真实偏离。

大半圆：
    使用已标定、重复性高的 Dcar_Arc。

第一小转角：
    保持 0.36 前进速度。
    转向需求打满。
    使用 DCar 原始短时相对 yaw 判断释放。

直线：
    保持 0.36 前进速度和零转向增量。
    使用“标定速度 × 8 ms × 指令次数”累计距离。

第二小转角：
    保持 0.36 前进速度。
    反方向转向需求打满。
    使用 DCar 原始短时相对 yaw 判断回正释放。

左右差异：
    左右各自使用独立的第一释放角、直线距离和第二释放角。

机械偏差累积：
    基础控制不长期追逐全局 X/Y。
    需要时由圆弧端点灰度地标提供有限 Y 修正。

实时性：
    运动期间不发送长串口。
    可选模块失效不阻止运动。
    最终停车后统一发送固定大小日志。
```

这套方案的核心不是弥补一个“不准确的里程计”，而是：

> 充分相信并利用 DCar 高精度里程计，同时正视二轮小车机械安装精度低于测量精度这一事实，用分段、局部、左右独立和事件地标修正的方法，把机械系统误差限制在可理解、可标定、可控制的范围内。
